## 1. 변수 및 아키텍처 일관성 유지

* **기존 네이밍 컨벤션 준수**: 기존에 정의된 변수명, 컴포넌트명, 헬퍼 함수명, 스타일 키명을 임의로 변경하거나 축약하지 않습니다.
* **최소 침습적 수정(Minimal-Diff)**: 불필요한 대규모 리팩토링이나 디렉토리 구조 변경을 금지하며, 요구된 기능 변경에 필요한 부분만 정밀하게 수정합니다.

---

## 2. 문법적 일관성 및 React 19 / RN 최적화

* **모던 표준 문법**: ES6+, React Hooks(`useState`, `useEffect`, `useMemo`, `useCallback`) 패턴을 일관되게 사용합니다.
* **렌더링 최적화**: FlatList 또는 대규모 리스트(시간표, 일지 목록) 렌더링 시 불필요한 리렌더링을 방지하고 `keyExtractor`, `useCallback` 등을 적극 활용하여 메모리와 성능을 최적화합니다.
* **New Architecture 호환성**: 외부 라이브러리 추가 시 React Native New Architecture(Fabric & TurboModules)를 지원하는지 반드시 확인합니다.

---

## 3. 코드 스타일 및 주석

* **가독성 최우선**: 기계적으로 생성된 boilerplate 느낌을 지양하고, 사람이 작성한 것처럼 직관적이고 깔끔한 구조를 유지합니다.
* **명확한 한국어 주석**: 복잡한 비즈니스 로직(주간 날짜 계산, 일지-학생 연쇄 삭제, 서명 키 연동 등)에는 개발자가 한눈에 파악할 수 있는 친절한 한국어 주석을 작성합니다.

## 5. 언어 및 타입 정책 (순수 JS + @types)

* **순수 JavaScript 유지**: 본 프로젝트는 순수 JavaScript(React Native / JSX) 환경을 유지하며, 임의로 TypeScript(`.ts`/`.tsx`)로 전면 전환하지 않습니다.
* **자동 완성 및 타입 힌트**: IDE 자동 완성과 타입 지원은 `devDependencies`의 `@types/*` 및 `tsconfig.json`을 기준으로 활용합니다.
* **선택적 정적 타입 검증**: DB 동기화, HWPX 생성, 스토리지 처리 등 정밀한 데이터 무결성이 요구되는 핵심 모듈에 한하여 파일 상단 `// @ts-check` 및 JSDoc을 선택적으로 적용합니다.
