# ⚖️ MyDiary 주요 기술 의사결정 기록 (Architecture Decision Records - ADR)

> **문서 목적**: MyDiary 프로젝트에서 내린 아키텍처 및 기술 스택 선정 이유, 대안 검토 결과 및 제약 조건을 기록한 단일 진실 공급원입니다. AI 에이전트가 기존 설계를 임의로 변경하지 않도록 방지합니다.

## ADR-001: 순수 JavaScript(React Native JSX) 유지 및 전면 TypeScript 전환 보류

* **일자**: 2026-09-15
* **상태**: `Accepted (결정됨)`
* **맥락**: 최근 모바일 생태계에서 TypeScript 사용이 일반적이나, MyDiary는 고도로 안정화된 단일 개발자 프로젝트입니다.
* **결정**:
  * 프로젝트 전면을 `.ts`/`.tsx`로 전환하지 않고 순수 JavaScript(JSX)를 유지합니다.
  * 타입 검증과 IDE 보조는 `devDependencies`의 `@types/*` 및 JSDoc(`// @ts-check`)을 핵심 모듈에 부분 적용합니다.
* **이유**: 전면 마이그레이션 시 발생할 수 있는 대규모 diff, 컴파일 빌드 복잡성 증가, 런타임 갭 위험을 방지하고 최소 침습적 개발 생산성을 극대화하기 위함입니다.

## ADR-002: 로컬 퍼스트(Local-first) AsyncStorage 채택 및 클라우드 DB 배제

* **일자**: 2026-09-20
* **상태**: `Accepted (결정됨)`
* **맥락**: 교습소/과외 교사의 특성상 인터넷 연결이 원활하지 않은 교실 환경에서도 즉각적인 일지 조회가 필요하며, 학생들의 민감한 개인정보(이름, 연락처, 수강료 차수)가 포함됩니다.
* **결정**:
  * 외부 클라우드 DB(Firebase, Supabase 등)에 종속되지 않고 100% 모바일 로컬 샌드박스(`AsyncStorage`)에만 데이터를 보관합니다.
  * 백업은 오직 사용자의 명시적 요청 시 본인의 개인 Google Drive에 `mydiary_backup.json`으로만 내보냅니다.
* **이유**: 데이터 보안 및 프라이버시 100% 보장, 서버 유지비용 0원 달성, 오프라인 완전 독립 구동 보장.

## ADR-003: 클라이언트 기기 내부 HWPX (KS X 6101 OWPML) 직접 생성 파이프라인

* **일자**: 2026-10-05
* **상태**: `Accepted (결정됨)`
* **맥락**: 한국 공교육 및 복지 기관에서는 보고서 양식으로 한글(.hwpx / .hwp) 문서를 필수로 요구합니다.
* **결정**:
  * 외부 변환 서버를 거치지 않고, 모바일 앱 내부에서 `jszip` 라이브러리를 이용하여 국가 표준 KS X 6101 OWPML XML 마크업(`section0.xml`, `header.xml` 등)을 실시간으로 빌드하고 압축하여 `.hwpx` 파일로 생성합니다.
* **이유**: 민감한 학생 평가 데이터가 외부 변환 서버로 유출되는 것을 원천 방지하고, 네트워크가 없는 환경에서도 즉시 한글 문서를 출력·공유할 수 있습니다.

## ADR-004: 모바일과 데스크톱의 공통 비즈니스 로직 동기화 및 UI 렌더링 격리

* **일자**: 2026-10-18
* **상태**: `Accepted (결정됨)`
* **맥락**: 스마트폰 앱(`mydiary`)과 PC 데스크톱 앱(`mydiary-desktop`) 간의 기능 패리티 유지가 필요합니다.
* **결정**:
  * `Database.js`의 스키마 명칭, 주간시간표 독립 저장 알고리즘, HWPX XML 태그 규격은 양방향 1:1 동기화합니다.
  * 단, UI 프레임워크(React Native vs React DOM)와 파일 I/O(Expo Sharing vs Electron fs)는 각 플랫폼의 고유 영역으로 엄격히 격리합니다.
